  secondary source if more families are needed.

## Grounded mechanism (verified in source)

- Theme packs: file-based, app/themes/<id>/theme.json (+ per-activity
  app/activities/<activity>/themes/<id>/theme.json). Keys: id, name, name_en,
  colors.light/dark (full token sets), fonts {body, display, files[]}, radius,
  shadows, motion. Validated by app/framework/manifest.py theme_problems.
- Real font delivery: theme fonts.files entries {family, src: "assets/<file>.ttf",
  weight, style}; the server serves them at /themes/assets/files/<id>/assets/<file>
  (app/platform/themes/service.py) and the client builds real @font-face rules
  (system/core/frontend/src/lib/theme.ts themeCss). FONT_FILE validation allows
  woff2/woff/ttf/otf.
- Workspace choice: tenants.palette {name, hue}; app/catalog/sectors.py
  PALETTE_HUES must list any new palette id with a hue. Signup POST /platform/signup
  takes palette; activity.json "theme" is the existing per-activity fallback.
- Onboarding wizard: website/frontend OnboardingWizard.tsx (3 steps: activity,
  company, appearance+modules). Its live palette preview is the marketing site's
  LOCAL uiStore (6 palettes), NOT the server theme system: the redesign applies the
  real theme pack via shared theme.ts applyTheme so the preview renders the true
  colors and the true bundled fonts.

## Plan

1. Palette catalog: original 4-8 role palettes composed from Open Color shades,
   each as a full theme pack (light + derived dark tokens, radius/shadows/motion
   reused from mizan defaults), generated by a committed script from oc.json +
   licenses. Each pack bundles the recommended font files in its assets dir.
2. activity.json gains a "branding" block per activity:
   {recommended_palettes: [theme ids], fonts: {arabic, latin}, notes}.
   Consumed by onboarding; never hardcoded in the wizard.
3. Wizard redesign: uncluttered steps; branding step shows the activity's
   recommended palettes first, then the full catalog; selecting a palette applies
   the REAL theme pack (true colors + true fonts) to the wizard preview; logo
   upload with preview before save; font choice previewed in real faces.
4. Follow-workspace: Site design gains a "follow workspace branding" option for
   logo/theme/fonts with a per-site override (dynamic updates with workspace
   settings). Scoped to the studio site settings document.
5. Proof: create-workspace through Studio end to end on the local stack,
   screenshots of each redesigned step with real fonts rendering, jsdom/driver
   tests. Deployment stays pending (parent holds redeploy authority check).
